Memilih Image yang Tepat untuk Root: Boot, Init Boot, atau Recovery

Pelajari cara memilih image yang tepat untuk root Magisk berdasarkan boot, init_boot, atau recovery serta risiko salah pilih partisi.

Published
15 Jan 2023
Updated
8 Jun 2025
Category
Android Modding, Root

Kesalahan umum saat root adalah mem-patch image yang salah. Targetnya tidak bisa ditentukan hanya dari versi Android yang sedang berjalan. Pada perangkat yang diluncurkan dengan Android 13, generic ramdisk dapat berada di init_boot.img; perangkat lain bisa memiliki layout berbeda. Periksa image firmware untuk model dan build tepat serta ikuti panduan perangkat dan Magisk. Pada perangkat tertentu, recovery dapat menjadi target.

Artikel ini menjelaskan cara menentukan image yang tepat berdasarkan perangkat, firmware, dan dokumentasi resmi.

Peringatan: Jangan menebak target patch. Salah image atau salah partisi dapat menyebabkan perangkat gagal boot.

Mengapa target root berbeda?

Target root berbeda karena struktur partisi Android berbeda.

Faktor yang memengaruhi:

  • Generasi Android.
  • Arsitektur SoC.
  • Keputusan produsen.
  • Struktur partisi.
  • Penggunaan GKI.
  • Penggunaan recovery-as-boot.

Android tidak memiliki satu layout partisi wajib. Yang diwajibkan adalah perilaku sistem, bukan nama dan susunan partisi. Karena itu, dua perangkat dengan versi Android sama dapat memiliki layout yang berbeda, dan satu perangkat dapat memiliki layout yang tidak lazim.

Isi partisi boot secara umum

Sebelum memilih image, pahami dulu apa yang biasanya ada di dalamnya.

Pemisahan ini muncul karena generic kernel image dan komponen vendor dipisahkan agar pembaruan kernel tidak bergantung pada vendor. Konsekuensinya, letak ramdisk dapat berpindah dari satu partisi ke partisi lain.

Image boot.img

boot.img umumnya memuat kernel dan, pada banyak generasi perangkat, ramdisk.

Pada perangkat yang masih memakai ramdisk di boot, target root biasanya adalah boot.img. Ini pola yang paling banyak ditemukan pada perangkat lama dan sebagian perangkat menengah.

Image init_boot.img

init_boot.img menyimpan generic ramdisk pada perangkat yang diluncurkan dengan Android 13. AOSP menjelaskan bahwa generic ramdisk dipindahkan dari boot ke init_boot pada perangkat tersebut.[2]

Artinya, pada perangkat tertentu, target root adalah init_boot.img, bukan boot.img. Mem-patch boot.img pada perangkat seperti ini tidak menghasilkan root, meskipun proses flashing berhasil.

Satu catatan penting: perangkat yang diperbarui ke Android 13 belum tentu memiliki init_boot. Yang menentukan adalah konfigurasi saat perangkat dirancang, bukan versi Android yang sedang berjalan.

Image recovery.img

Pada perangkat tertentu, recovery dapat menjadi target patch Magisk. Dokumentasi Magisk menyebut opsi patch boot/init_boot/recovery.

Namun, ini bukan pola universal. Jangan mematch recovery hanya karena tutorial lain melakukannya. Pada perangkat dengan recovery-as-boot, image recovery justru menyatu dengan boot, sehingga targetnya berbeda lagi.

Cara menentukan image yang tepat

Beberapa sumber yang dapat dipakai sebagai pembanding:

  • Halaman resmi Magisk dan catatan rilisnya.
  • Halaman instalasi ROM yang dipakai perangkat.
  • Dokumentasi vendor atau paket firmware resmi.
  • Catatan maintainer untuk perangkat tersebut.

Bila dua sumber berbeda, jangan memilih yang paling mudah. Periksa isi paket firmware resmi untuk build yang sedang berjalan, lalu cocokkan dengan panduan perangkat.

Memeriksa image sebelum patch

Sebelum mem-patch, lakukan pemeriksaan dasar pada file yang Anda unduh:

  • Nama file sesuai dengan panduan perangkat.
  • Ukuran file wajar untuk image boot, bukan paket firmware penuh.
  • Build dan model sesuai dengan perangkat.
  • File berasal dari sumber resmi atau paket firmware resmi.

Image boot hasil ekstraksi dari paket firmware vendor biasanya sudah benar karena berasal dari build yang sama. Image dari unggahan pihak ketiga memiliki risiko tambahan: bisa berasal dari build berbeda, perangkat berbeda, atau sudah dimodifikasi.

Perintah ini hanya membaca informasi dari bootloader. Nama variabel dan ketersediaannya dapat berbeda antarperangkat.

Membaca paket firmware resmi

Cara paling dapat diandalkan untuk mendapatkan image yang tepat adalah mengambilnya dari paket firmware resmi untuk build yang sedang berjalan.

Alurnya secara umum:

  1. Catat build number dan codename perangkat.
  2. Unduh paket firmware resmi untuk build tersebut.
  3. Ekstrak paket sesuai format vendor.
  4. Ambil image boot yang sesuai.
  5. Cocokkan nama dan ukuran dengan panduan perangkat.

Format paket berbeda antar vendor. Sebagian berupa arsip biasa, sebagian berupa paket terenkripsi, dan sebagian memerlukan alat resmi vendor untuk mengekstrak. Bila paket tidak dapat diekstrak dengan cara yang jelas, jangan memaksakan diri memakai image dari sumber tidak resmi.

Keuntungan memakai image dari paket resmi:

  • Berasal dari build yang sama dengan perangkat.
  • Tidak mengandung modifikasi pihak ketiga.
  • Dapat diverifikasi ulang kapan saja.

Kerugiannya adalah proses ekstraksi yang berbeda per vendor dan kadang tidak sederhana.

Contoh kasus perangkat

Tiga pola yang cukup umum:

Perangkat lama dengan partisi recovery terpisah. Ramdisk berada di boot, dan recovery memiliki partisinya sendiri. Target root biasanya boot.img, dan recovery dapat dipakai sebagai jalur pemulihan.

Perangkat A/B modern dengan recovery-as-boot. Tidak ada partisi recovery terpisah. Recovery menyatu dengan boot, sehingga memperlakukan boot sebagai target root sekaligus jalur pemulihan menuntut kehati-hatian.

Perangkat yang diluncurkan dengan Android 13. Generic ramdisk berada di init_boot, sedangkan boot tetap memuat kernel. Target patch adalah init_boot.img.

Pola di atas bukan daftar lengkap. Perangkat dengan konfigurasi vendor khusus dapat menyimpang dari ketiganya.

Perbandingan image

Risiko pada baris recovery.img lebih tinggi karena recovery juga menjadi jalur pemulihan. Bila recovery rusak, kemampuan memperbaiki perangkat ikut berkurang.

Risiko salah pilih image

  • Bootloop.
  • Perangkat gagal boot.
  • Root gagal.
  • Recovery rusak.
  • OTA gagal.
  • Firmware tidak kompatibel.

Dampak paling ringan adalah root tidak terpasang meskipun perangkat masih boot. Dampak paling berat adalah perangkat tidak dapat masuk ke sistem maupun recovery, sehingga pemulihan bergantung pada alat vendor atau layanan resmi.

Miskonsepsi umum

“Semua perangkat mematch boot.img.”

Tidak. Target bergantung pada layout perangkat. Pada perangkat yang diluncurkan dengan Android 13, generic ramdisk dapat berada di init_boot.img; verifikasi image dan panduan khusus perangkat sebelum patch.[2]

“Recovery selalu jadi target root.”

Tidak. Recovery hanya relevan pada perangkat tertentu.

“Versi Android sama, berarti target sama.”

Tidak. Struktur partisi dan firmware dapat berbeda.

“Magisk otomatis memilih image yang benar.”

Tidak. Pengguna tetap harus memilih file yang tepat.

“Image dari model yang sama pasti cocok.”

Belum tentu. Build, region, dan varian dapat berbeda. Image harus sesuai dengan build yang sedang berjalan, bukan hanya nama model.

Checklist sebelum patch

  • Codename terverifikasi.
  • Firmware sesuai.
  • Struktur partisi diketahui.
  • Dokumentasi Magisk dibaca.
  • Image yang tepat sudah dipilih.
  • Backup selesai.
  • Jalur pemulihan tersedia.
