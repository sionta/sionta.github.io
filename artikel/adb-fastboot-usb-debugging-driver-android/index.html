Mengenal ADB, Fastboot, USB Debugging, dan Driver Android

Pelajari perbedaan ADB dan Fastboot, cara kerja USB debugging, fungsi driver Android, serta persiapan aman sebelum melakukan modding.

Published
26 Jan 2020
Updated
11 Dec 2022
Category
Android Modding, Fundamentals

ADB dan Fastboot adalah dua alat baris perintah yang paling penting dalam Android modding. Keduanya memungkinkan komputer berkomunikasi dengan perangkat Android, tetapi bekerja pada kondisi dan tingkat akses yang berbeda.

ADB umumnya digunakan saat Android masih dapat berjalan normal, sedangkan Fastboot digunakan saat perangkat berada di mode bootloader. Memahami perbedaan ini membantu mencegah kebingungan seperti “perangkat terdeteksi ADB tetapi tidak terdeteksi Fastboot”.

Apa itu ADB?

ADB atau Android Debug Bridge adalah alat serbaguna untuk mengelola perangkat Android atau emulator dari komputer. Android Developers menjelaskan bahwa ADB dapat digunakan untuk mengelola status perangkat atau emulator, termasuk menginstal APK.[2]

Dalam konteks modding, ADB biasanya digunakan untuk:

  • Memeriksa apakah perangkat terdeteksi oleh komputer.
  • Menyalin file tertentu dari atau ke perangkat.
  • Menginstal aplikasi.
  • Mengambil log untuk diagnosis masalah.
  • Menjalankan perintah shell tertentu bila izin sistem mengizinkan.
  • Membantu proses sideload melalui recovery, tergantung dukungan perangkat.

Note

ADB bukan alat untuk “membuka” semua sistem Android secara otomatis. Kemampuannya tetap dibatasi oleh izin, status perangkat, dan kebijakan keamanan Android.

Apa itu Fastboot?

Fastboot adalah nama modul dan mode bootloader. AOSP menjelaskan bahwa Fastboot merupakan modul bootloader sekaligus mode untuk berinteraksi dengan perangkat.[4]

Fastboot digunakan untuk tindakan tingkat rendah seperti:

  • Memeriksa apakah perangkat terdeteksi dalam mode bootloader.
  • Melakukan flashing image tertentu, bila bootloader mengizinkan.
  • Boot image sementara pada perangkat yang mendukungnya.
  • Unlock atau lock bootloader, sesuai mekanisme resmi vendor.
  • Reboot ke mode tertentu.

Note

Fastboot berbeda dari ADB karena biasanya bekerja ketika Android normal tidak sedang berjalan. Perangkat harus berada dalam mode Fastboot atau bootloader agar dapat dikenali oleh perintah Fastboot.

Perbedaan ADB dan Fastboot

Warning

Perbedaan paling penting: ADB tidak menggantikan Fastboot. Jika perangkat berada di mode bootloader, adb devices biasanya tidak akan menampilkan perangkat; gunakan fastboot devices.

Apa itu USB debugging?

USB debugging adalah opsi pengembang yang mengizinkan komputer berkomunikasi dengan perangkat Android melalui ADB. Dokumentasi Android Developers menyatakan bahwa untuk menggunakan ADB melalui USB, USB debugging harus diaktifkan di Developer options.[2]

USB debugging diperlukan untuk banyak tugas ADB, tetapi tidak otomatis berarti perangkat sudah tidak aman. Android tetap menerapkan mekanisme otorisasi sebelum komputer dapat menjalankan perintah ADB.

Cara kerja otorisasi ADB

Saat perangkat Android 4.2.2 atau lebih baru terhubung ke komputer untuk debugging, Android menampilkan dialog untuk menerima atau menolak RSA key dari komputer tersebut.

Android Developers menjelaskan bahwa USB debugging dan perintah ADB lainnya tidak dapat dijalankan kecuali pengguna membuka kunci perangkat dan menyetujui dialog tersebut.

Caution

Komputer asing tidak dapat langsung menjalankan ADB hanya karena kabel terpasang. Pengguna harus membuka layar dan menyetujui sidik jari RSA yang muncul. Jangan menyetujui dialog RSA pada komputer yang tidak Anda kenali.

Mengaktifkan Developer Options dan USB debugging

Langkah umumnya adalah sebagai berikut:

  1. Buka Settings atau Pengaturan.
  2. Masuk ke About phone atau Tentang ponsel.
  3. Ketuk Build number atau Nomor bentukan sebanyak tujuh kali.
  4. Kembali ke menu pengaturan.
  5. Buka System → Developer options.
  6. Aktifkan USB debugging.

Note

Dokumentasi AOSP menjelaskan pola yang sama: buka About phone, ketuk build number tujuh kali hingga muncul pesan developer mode, lalu aktifkan USB debugging dari Developer options. Lokasi menu dapat berbeda antarprodusen dan versi Android.

Apa itu driver Android?

Driver adalah perangkat lunak di komputer yang membuat sistem operasi komputer mengenali perangkat Android yang terhubung.

Driver yang diperlukan dapat berbeda menurut:

  • Sistem operasi komputer, misalnya Windows, Linux, atau macOS.
  • Produsen perangkat.
  • Model dan chipset perangkat.
  • Mode perangkat: Android normal, ADB, Fastboot, recovery, atau mode pemulihan vendor.

Tip

Pada Windows, masalah driver adalah penyebab umum perangkat tidak terdeteksi. Pada Linux dan macOS, dukungan sistem dapat berbeda, tetapi konfigurasi izin dan aturan udev tetap dapat menjadi faktor pada beberapa distribusi Linux.

Mengapa perangkat terdeteksi ADB tetapi tidak Fastboot?

Ini adalah salah satu kebingungan paling umum. Penyebabnya biasanya bukan karena ADB rusak, melainkan karena ADB dan Fastboot memakai mode perangkat yang berbeda.

Kemungkinan penyebabnya:

  • Perangkat belum berada di mode bootloader atau Fastboot.
  • Driver Fastboot belum terpasang dengan benar, terutama di Windows.
  • Kabel USB hanya mendukung pengisian daya atau kualitasnya buruk.
  • Port USB komputer bermasalah.
  • Perangkat menggunakan mode Fastboot berbeda, misalnya FastbootD, tergantung implementasi vendor.
  • Perangkat memiliki pembatasan vendor atau kondisi bootloader tertentu.

AOSP menjelaskan bahwa Fastboot adalah modul dan mode bootloader.[4] Karena itu, perangkat harus benar-benar berada pada mode tersebut agar dapat dikenali oleh Fastboot.

Perintah dasar yang perlu dipahami

Berikut hanya perintah pemeriksaan, bukan perintah flashing. Perintah flashing akan dibahas pada artikel persiapan dan unlock bootloader dengan pengantar risiko yang lengkap.

Memeriksa perangkat

Perintah ini menampilkan daftar perangkat yang terdeteksi oleh ADB. Bila perangkat terdeteksi tetapi statusnya unauthorized, berarti otorisasi RSA belum diterima di layar HP.

Perintah ini hanya berguna ketika perangkat berada di mode bootloader/Fastboot dan driver serta koneksi sudah benar.

Reboot ke bootloader

Perintah ini meminta perangkat untuk reboot ke mode bootloader. AOSP mendokumentasikan adb reboot bootloader sebagai salah satu cara memasuki Fastboot mode.

Note

Nama mode dan perilaku reboot dapat berbeda antarvendor. Pada beberapa perangkat, pengguna perlu memakai kombinasi tombol fisik atau menu khusus produsen.

Kabel, port, dan listrik

Kualitas koneksi fisik sering diabaikan, padahal sangat menentukan.

  • Pakai kabel USB yang mendukung transfer data, bukan kabel charge-only.
  • Coba port USB langsung di komputer, bukan melalui hub.
  • Hindari port USB yang longgar atau kabel yang sering terputus.
  • Pastikan baterai perangkat cukup sebelum proses apa pun.
  • Jangan mencabut kabel saat proses transfer atau flashing berlangsung.

Tip

Kabel yang baik tidak menjamin proses modding berhasil, tetapi kabel buruk dapat membuat diagnosis menjadi jauh lebih sulit.

Keamanan ADB dan USB debugging

USB debugging meningkatkan kemampuan komputer untuk berinteraksi dengan perangkat. Karena itu, aktifkan hanya saat diperlukan.

Praktik aman:

  • Jangan menyetujui RSA key dari komputer umum, warnet, atau komputer yang bukan milik Anda.
  • Matikan USB debugging setelah selesai digunakan.
  • Jangan menjalankan skrip ADB dari sumber tidak dikenal.
  • Periksa perintah sebelum menyalinnya ke terminal.
  • Jangan memberikan perangkat dalam kondisi USB debugging aktif kepada orang yang tidak dipercaya.

Hubungan ADB, Fastboot, dan modding

ADB sering menjadi langkah awal untuk masuk ke mode bootloader. Setelah perangkat berada di mode bootloader, Fastboot yang mengambil alih komunikasi. Namun, urutan ini tidak berlaku mutlak untuk semua perangkat.

Miskonsepsi umum

“ADB dan Fastboot sama saja.” Tidak. ADB bekerja saat Android normal berjalan; Fastboot bekerja pada mode bootloader.

“USB debugging membuat HP langsung bisa di-root.” Tidak. USB debugging hanya mengizinkan komunikasi ADB. Root memerlukan metode dan prasyarat tersendiri.

“Kalau adb devices kosong, HP pasti rusak.” Belum tentu. Penyebabnya bisa berupa kabel, port USB, driver, USB debugging nonaktif, atau dialog otorisasi yang belum disetujui.

“Driver universal aman untuk semua HP.” Tidak selalu. Driver dapat bergantung pada produsen, chipset, dan mode perangkat. Gunakan driver resmi atau sumber tepercaya sesuai model perangkat.

“Fastboot pasti bisa memperbaiki semua HP.” Tidak. Fastboot dapat membantu pada banyak kasus, tetapi tidak semua perangkat dapat dipulihkan melalui Fastboot. Kemampuannya bergantung pada bootloader, vendor, dan kondisi perangkat.

Checklist sebelum lanjut

Sebelum melanjutkan ke artikel berikutnya, pastikan Anda:

  • Memahami perbedaan ADB dan Fastboot.
  • Tahu di mana menu Developer options berada pada perangkat Anda.
  • Paham bahwa USB debugging memerlukan otorisasi RSA.
  • Tahu bahwa adb devices dan fastboot devices mengecek mode yang berbeda.
  • Memiliki kabel USB yang mendukung transfer data.
  • Tidak akan menyetujui RSA key pada komputer yang tidak dipercaya.
