Partisi Boot, Recovery, Vendor Boot, dan Init Boot pada Android

Pelajari peran partisi boot, recovery, vendor_boot, dan init_boot pada Android serta mengapa target flashing recovery atau root berbeda antarperangkat.

Published
7 Mar 2021
Updated
10 Mar 2024
Category
Android Modding, Recovery

Tidak semua perangkat Android memiliki struktur partisi yang sama. Pada beberapa perangkat, recovery berada di partisi recovery; pada perangkat lain, recovery berada di boot atau vendor_boot. Perangkat yang diluncurkan dengan Android 13 dapat menempatkan generic ramdisk di init_boot, tetapi versi Android yang sedang berjalan tidak cukup untuk memastikan layout itu.

Memahami perbedaan ini penting karena kesalahan memilih partisi target dapat menyebabkan perangkat gagal boot.

Peringatan: Artikel ini menjelaskan konsep partisi, bukan perintah flashing. Jangan menjalankan fastboot flash boot, fastboot flash recovery, atau fastboot flash vendor_boot kecuali dokumentasi resmi perangkat Anda mengonfirmasi partisi dan image yang tepat.

Mengapa partisi boot penting?

Partisi terkait boot menyimpan komponen yang dibutuhkan untuk memulai Android, seperti kernel, ramdisk, device tree, dan komponen vendor.

Perangkat Android modern dapat menggunakan kombinasi partisi berikut:

  • boot
  • init_boot
  • vendor_boot
  • recovery
  • dtbo
  • vendor_dlkm
  • system_dlkm

Tidak semua perangkat memiliki semua partisi tersebut. Kombinasinya bergantung pada generasi Android, arsitektur SoC, dan keputusan produsen.

Partisi boot

Partisi boot umumnya menyimpan komponen inti untuk proses boot, termasuk kernel dan—pada banyak generasi perangkat—ramdisk.

Android 11 memperkenalkan Generic Kernel Image atau GKI. Pada perangkat yang memakai GKI, komponen boot khusus vendor dapat ditempatkan di vendor_boot; layout aktual bergantung pada perangkat.[1][4]

Artinya, pada perangkat yang lebih baru, boot cenderung lebih “generik”, sementara komponen spesifik vendor dipindahkan ke partisi terpisah.

Peran boot dalam modding

boot sering menjadi target penting untuk:

  • Recovery-as-boot pada perangkat tertentu.
  • Kernel custom.
  • Patch root pada perangkat yang masih memakai ramdisk di boot.
  • Pemulihan bila image boot rusak.

Namun, boot bukan selalu target root atau recovery. Pada perangkat yang diluncurkan dengan Android 13, generic ramdisk dapat berada di init_boot; versi Android yang sedang berjalan saja tidak memastikan layout tersebut.[2]

Partisi init_boot

Partisi init_boot menyimpan generic ramdisk pada perangkat yang diluncurkan dengan Android 13. AOSP menjelaskan bahwa pada perangkat tersebut, generic ramdisk dipindahkan dari image boot ke image init_boot.[2]

Mengapa init_boot penting?

Pada perangkat yang memakai init_boot, proses root atau modifikasi ramdisk mungkin perlu menyasar init_boot, bukan boot.

Ini menjelaskan mengapa dua perangkat dengan versi Android sama dapat memakai target patch berbeda:

Jangan menyimpulkan target hanya dari versi Android. Perangkat yang diperbarui ke Android 13 belum tentu memiliki struktur partisi yang sama dengan perangkat yang diluncurkan langsung dengan Android 13.

Partisi vendor_boot

Partisi vendor_boot menyimpan komponen boot yang spesifik vendor. AOSP menjelaskan bahwa boot image header version 3 memisahkan informasi boot khusus vendor ke vendor_boot.[4]

Dengan kata lain, vendor_boot membantu memisahkan komponen generik dari komponen yang bergantung pada vendor atau SoC.

Isi umum vendor_boot

vendor_boot dapat memuat:

  • Vendor ramdisk.
  • Komponen device tree atau konfigurasi vendor.
  • Sumber daya recovery vendor, tergantung konfigurasi perangkat.
  • Komponen yang diperlukan untuk mendukung GKI.

AOSP menjelaskan bahwa pada konfigurasi tertentu, recovery resources dapat dibuat sebagai recovery ramdisk terpisah di vendor_boot.[5]

Peran vendor_boot dalam modding

Pada beberapa perangkat, recovery dapat berada di vendor_boot. Halaman instalasi LineageOS untuk perangkat tertentu menunjukkan recovery dapat berupa vendor_boot.img dan di-flash ke partisi vendor_boot.

Ini adalah alasan mengapa perintah fastboot flash recovery recovery.img tidak selalu benar. Pada perangkat tertentu, target yang tepat bisa jadi vendor_boot.

Partisi recovery

Partisi recovery menyimpan recovery pada perangkat yang masih memakai partisi recovery terpisah.

Pada perangkat seperti ini, recovery image biasanya bernama recovery.img dan target flashing adalah recovery. Halaman instalasi LineageOS untuk beberapa perangkat menunjukkan pola tersebut.

Kapan recovery masih relevan?

Partisi recovery masih relevan pada:

  • Perangkat non-A/B tertentu.
  • Perangkat lama.
  • Perangkat yang tidak memakai recovery-as-boot.
  • Perangkat yang dokumentasinya secara eksplisit menyebut partisi recovery.

Namun, jangan mengasumsikan semua perangkat modern masih memakai partisi recovery terpisah.

Recovery-as-boot

Recovery-as-boot adalah pendekatan ketika recovery tidak berada di partisi recovery terpisah, melainkan berada dalam image boot atau komponen boot terkait.

AOSP merekomendasikan recovery-as-boot untuk perangkat A/B, tetapi implementasi recovery tetap berbeda antarperangkat. Beberapa perangkat memakai partisi recovery khusus, sementara yang lain menyimpan komponennya di boot atau vendor_boot.

Implikasinya:

  • Recovery dapat berada di boot.
  • Recovery dapat berada di vendor_boot pada konfigurasi tertentu.
  • Perintah fastboot flash recovery mungkin tidak valid.
  • Target yang benar harus dilihat dari dokumentasi perangkat.

Perbandingan partisi

Tabel ini bersifat konseptual. Struktur nyata tetap ditentukan oleh produsen, codename, dan firmware perangkat.

Mengapa target recovery berbeda?

Target recovery berbeda karena evolusi arsitektur Android:

  1. Perangkat lama sering memakai partisi recovery terpisah.
  2. Perangkat A/B dapat memakai recovery-as-boot.
  3. Perangkat dengan GKI dapat memisahkan komponen vendor ke vendor_boot, sesuai konfigurasi perangkat.
  4. Perangkat yang diluncurkan dengan Android 13 dapat menempatkan generic ramdisk di init_boot; verifikasi layout perangkat.
  5. Vendor dapat menempatkan recovery resources di lokasi berbeda sesuai konfigurasi perangkat.

Dokumentasi LineageOS memperlihatkan perbedaan nyata antarperangkat: recovery dapat berupa recovery.img, boot.img, atau vendor_boot.img.

Mengapa target root juga berbeda?

Root sering dilakukan dengan mem-patch image yang memuat ramdisk atau komponen boot tertentu. Karena ramdisk dapat berada di boot atau init_boot, target patch dapat berbeda.

Pada perangkat yang diluncurkan dengan Android 13, AOSP menjelaskan bahwa generic ramdisk dipindahkan dari boot ke init_boot.[2] Karena layout dapat berbeda pada perangkat yang diperbarui ke Android 13, verifikasi image firmware dan panduan model tepat sebelum memilih target patch.

Namun, keputusan akhir tetap harus berdasarkan:

  • Codename perangkat.
  • Firmware yang terpasang.
  • Dokumentasi Magisk atau metode root.
  • Dokumentasi ROM atau komunitas perangkat.
  • Verifikasi pada perangkat fisik.

Risiko salah memilih partisi

Salah memilih partisi dapat menyebabkan:

  • Perangkat gagal boot.
  • Recovery tidak dapat diakses.
  • Kernel tidak termuat.
  • Root gagal atau bootloop.
  • OTA gagal diterapkan.
  • Firmware vendor tidak kompatibel.
  • Perangkat sulit dipulihkan.

Kesalahan paling berbahaya adalah mem-flash image untuk perangkat lain ke partisi perangkat Anda. Dua perangkat dengan merek sama dapat memiliki kernel, device tree, ramdisk, dan konfigurasi vendor yang berbeda.

Miskonsepsi umum

“Semua HP punya partisi recovery.”

Tidak selalu. A/B tidak menentukan sendiri lokasi recovery; perangkat dapat memakai recovery-as-boot atau partisi recovery khusus. Periksa dokumentasi untuk model dan codename tepat sebelum memilih image atau target.

“boot dan init_boot selalu sama.”

Tidak. Pada perangkat yang diluncurkan dengan Android 13, generic ramdisk dipindahkan dari boot ke init_boot.[2]

“vendor_boot hanya untuk vendor, jadi tidak relevan untuk recovery.”

Tidak selalu. AOSP menjelaskan bahwa recovery resources dapat ditempatkan sebagai recovery ramdisk terpisah di vendor_boot pada konfigurasi tertentu.[5]

“Recovery selalu di-flash ke recovery.”

Tidak. LineageOS menunjukkan recovery dapat berupa recovery.img, boot.img, atau vendor_boot.img, tergantung perangkat.

“Versi Android sama, berarti target root sama.”

Tidak. Perangkat yang diperbarui ke Android 13 belum tentu memiliki struktur partisi yang sama dengan perangkat yang diluncurkan langsung dengan Android 13.

Checklist sebelum flashing image boot

Sebelum melakukan flashing image terkait boot, pastikan:

  • Codename dan model number terverifikasi.
  • Firmware dasar sesuai.
  • Nama image sesuai dokumentasi resmi.
  • Partisi target sesuai dokumentasi resmi.
  • Recovery atau ROM kompatibel dengan perangkat.
  • Backup data sudah selesai dan tersimpan di luar perangkat.
  • Firmware resmi untuk pemulihan tersedia.
  • Perangkat terdeteksi Fastboot.
  • Anda memahami bahwa salah partisi dapat menyebabkan gagal boot.
  • Prosedur telah diuji pada perangkat fisik sebelum dipublikasikan.
