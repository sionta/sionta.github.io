Backup, Restore, dan ADB Sideload di Recovery Android

Pelajari cara kerja backup, restore, dan ADB sideload di recovery Android, termasuk batasan backup TWRP dan langkah aman sebelum instalasi custom ROM.

Published
21 Mar 2021
Updated
14 Apr 2024
Category
Android Modding, Recovery

Recovery bukan hanya tempat untuk factory reset. Pada banyak perangkat, recovery juga digunakan untuk backup, restore, dan ADB sideload—tiga operasi penting sebelum memasang custom ROM atau melakukan modifikasi sistem.

Namun, setiap operasi memiliki batasan. Backup recovery tidak selalu menyelamatkan seluruh penyimpanan internal, dan ADB sideload bukan metode universal untuk semua ROM.

Prinsip utama: Backup terlebih dahulu, verifikasi hasilnya, baru lakukan restore atau sideload. Jangan menjalankan wipe, factory reset, atau sideload tanpa memahami konsekuensinya.

Apa itu backup di recovery?

Backup recovery adalah proses menyimpan salinan partisi atau komponen sistem tertentu ke penyimpanan yang dapat diakses recovery.

Pada custom recovery seperti TWRP, backup dapat mencakup partisi seperti:

  • boot
  • system
  • vendor
  • data atau userdata
  • dtbo
  • vendor_boot, bila didukung perangkat

Daftar partisi yang dapat dibackup bergantung pada perangkat, recovery, dan struktur partisi yang tersedia.

Apa yang tidak dicakup backup recovery?

Kesalahan paling berbahaya adalah menganggap backup recovery menyelamatkan semua data.

TWRP menjelaskan bahwa di dalam /data terdapat folder /data/media yang berisi isi yang biasa dianggap sebagai internal storage atau penyimpanan internal. 1

TWRP juga menyatakan bahwa backup partisi userdata tidak menyertakan /data/media. 2

Artinya:

Foto, video, dokumen, dan file di penyimpanan internal tetap perlu disalin secara terpisah ke komputer, drive eksternal, atau cloud storage.

Jenis backup yang disarankan

1. Backup file pengguna

Backup ini paling penting dan harus dilakukan sebelum modding apa pun.

Simpan:

  • Foto dan video.
  • Dokumen.
  • Rekaman audio.
  • File kerja atau sekolah.
  • Kontak dan kalender.
  • Data aplikasi penting.

Gunakan minimal dua lokasi penyimpanan berbeda, misalnya komputer dan cloud storage.

2. Backup aplikasi tertentu

Beberapa aplikasi memiliki sistem backup sendiri:

  • WhatsApp dan aplikasi pesan lain.
  • Authenticator untuk kode 2FA.
  • Password manager.
  • Game dengan cloud save.
  • Aplikasi perbankan atau dompet digital.

Jangan mengandalkan backup recovery untuk data aplikasi yang memiliki mekanisme enkripsi atau sinkronisasi khusus.

3. Backup partisi recovery

Backup partisi recovery berguna untuk menyimpan kondisi sistem tertentu, misalnya boot, system, vendor, atau data.

Namun, backup ini bergantung pada:

  • Recovery yang digunakan.
  • Dukungan perangkat.
  • Struktur partisi.
  • Ruang penyimpanan yang tersedia.
  • Kompatibilitas restore dengan ROM atau firmware.

Backup di TWRP

TWRP menyediakan fitur backup melalui antarmuka dan juga melalui OpenRecoveryScript. Dokumentasi resmi TWRP menjelaskan perintah backup untuk membackup partisi tertentu, dengan beberapa partisi dapat dipilih sekaligus. 3

Prinsip backup TWRP

Sebelum membuat backup:

  • Pastikan penyimpanan tujuan cukup.
  • Gunakan penyimpanan eksternal bila tersedia dan didukung.
  • Jangan menyimpan satu-satunya backup di penyimpanan internal.
  • Catat partisi yang dibackup.
  • Verifikasi file backup dapat diakses.
  • Jangan menganggap backup data mencakup /data/media. 21

Partisi yang umum dibackup

Jangan mengasumsikan semua partisi tersedia atau dapat dibackup pada semua perangkat.

Apa itu restore di recovery?

Restore adalah proses mengembalikan backup yang sebelumnya dibuat ke perangkat.

Restore dapat berguna bila:

  • Update ROM menyebabkan masalah.
  • Modul root menyebabkan bootloop.
  • Sistem tidak stabil setelah modifikasi.
  • Anda ingin kembali ke kondisi tertentu.

Namun, restore bukan solusi universal.

Batasan restore

  • Backup harus dibuat dari recovery dan perangkat yang sesuai.
  • Restore dapat gagal bila struktur partisi berubah.
  • Restore data dari ROM berbeda dapat menyebabkan masalah.
  • Restore tidak mengembalikan file di /data/media bila bagian tersebut tidak ikut dibackup.
  • Restore tidak selalu kompatibel dengan firmware atau versi Android yang berbeda.

Jangan melakukan restore lintas perangkat, lintas codename, atau dari backup yang tidak jelas asalnya.

Apa itu ADB sideload?

ADB sideload adalah mode khusus yang memungkinkan komputer mengirim paket ZIP ke recovery untuk diproses. Mode ini sering dipakai untuk menginstal OTA, custom ROM, atau paket pembaruan tertentu.

TWRP menyatakan bahwa ADB sideload didukung sejak TWRP 2.3 dan merupakan mode ADB berbeda yang dapat digunakan untuk mengirim serta menginstal ZIP dengan satu perintah. 4

Pada recovery, perangkat dapat muncul sebagai recovery atau sideload pada adb devices. 5

Kapan ADB sideload digunakan?

ADB sideload umumnya digunakan untuk:

  • Menginstal custom ROM yang menyediakan paket ZIP.
  • Menerapkan pembaruan ROM secara manual.
  • Menginstal paket tertentu sesuai dokumentasi ROM.
  • Mengirim file pembaruan tanpa menyalinnya terlebih dahulu ke penyimpanan internal.

ADB sideload bukan metode untuk:

  • Mem-flash image .img seperti boot.img atau recovery.img.
  • Memperbaiki semua kondisi bootloop.
  • Mengganti recovery.
  • Menginstal ROM untuk perangkat lain.

Alur umum ADB sideload

Alur berikut adalah pola umum, bukan prosedur universal:

Pada beberapa halaman instalasi LineageOS, pengguna memilih Apply update → Apply from ADB lalu mengirim paket ZIP dengan adb -d sideload. Langkah tepat setelahnya berbeda antarperangkat; ikuti halaman model yang sesuai. 6

LineageOS memperingatkan pengguna agar tidak reboot ke sistem sebelum membaca dan menyelesaikan instruksi instalasi perangkat. ROM dapat memiliki langkah tambahan setelah sideload. 6

Persiapan sebelum sideload

Sebelum memulai sideload, pastikan:

  • File ZIP benar untuk codename perangkat.
  • File diunduh dari sumber resmi.
  • Versi ROM sesuai dengan firmware dasar.
  • Recovery kompatibel dengan ROM.
  • Backup data sudah selesai.
  • Baterai perangkat cukup.
  • Kabel USB mendukung transfer data.
  • Perangkat terdeteksi oleh ADB dalam mode recovery atau sideload.
  • Anda sudah membaca seluruh instruksi instalasi ROM.
  • Anda tahu langkah lanjutan setelah sideload selesai.

Risiko ADB sideload

1. Sideload file yang salah

File ZIP untuk perangkat lain dapat menyebabkan kegagalan instalasi atau perangkat gagal boot.

2. Sideload di recovery yang tidak kompatibel

Recovery lama mungkin tidak mendukung ROM modern, dynamic partitions, atau format paket tertentu.

3. Reboot terlalu cepat

Beberapa ROM memerlukan langkah tambahan setelah sideload. Reboot ke sistem terlalu dini dapat menyebabkan instalasi tidak lengkap. 6

4. Kehilangan data

Beberapa ROM atau prosedur instalasi memerlukan format data. Jangan mengasumsikan sideload selalu aman terhadap data.

5. Kegagalan transfer

Kabel buruk, port USB bermasalah, atau driver tidak tepat dapat membuat sideload gagal di tengah proses.

Backup vs restore vs sideload

Miskonsepsi umum

“Backup TWRP menyelamatkan semua foto.”

Tidak. TWRP menyatakan backup userdata tidak menyertakan /data/media. 2

“ADB sideload bisa mem-flash boot.img.”

Tidak selalu. ADB sideload umumnya untuk paket ZIP; image .img biasanya ditangani melalui Fastboot atau metode lain sesuai dokumentasi perangkat.

“Sideload ROM selalu menghapus data.”

Tidak selalu, tetapi beberapa prosedur instalasi memerlukan format data. Selalu ikuti dokumentasi ROM.

“Restore backup dari HP lain aman.”

Tidak. Restore harus sesuai perangkat, codename, recovery, dan struktur partisi.

“Setelah sideload, langsung reboot.”

Tidak selalu. Beberapa ROM memiliki langkah lanjutan dan melarang reboot ke sistem sebelum instruksi selesai. 6

Checklist sebelum sideload

  • Backup file pengguna selesai dan terverifikasi.
  • Backup aplikasi penting selesai.
  • Kode 2FA dan kode pemulihan tersimpan aman.
  • File ZIP sesuai codename perangkat.
  • File ZIP berasal dari sumber resmi.
  • Firmware dasar sesuai.
  • Recovery kompatibel.
  • Baterai cukup.
  • Kabel dan port USB berfungsi.
  • Perangkat terdeteksi dalam mode recovery atau sideload.
  • Seluruh instruksi ROM sudah dibaca.
  • Langkah setelah sideload sudah dipahami.
